*which-key.txt*  Native keybinding hints

KEYBINDING HINTS                                 *better-start-nvim-which-key*

Pause after a mapped prefix in Normal or Visual mode to see its continuations
in a bottom panel. Type <leader>p for project actions or <leader><Tab> for
workspaces. Continue typing to narrow the choices and execute a mapping;
<Esc> or <C-c> cancels. This first-party module has no plugin dependencies.

Part of |better-start-nvim|.

==============================================================================
TIMING AND LAYOUT                         *better-start-nvim-which-key-layout*

The panel discovers global and buffer-local mappings; buffer-local mappings
take precedence. Labels use a mapping's desc, then its right-hand side, then
"Lua callback". A + entry leads to another group. Built-in commands without
configured mappings are absent; unlisted continuations such as gg, zz, and
<C-w>w still execute through Neovim.

lua/options.lua sets 'timeoutlen' to 400 milliseconds. Native mapping
resolution reaches that timeout before invoking a prefix trigger; the module
adds no popup timer. Keep 'timeout' enabled for timed triggers. Terminal
keycode timeouts are unchanged. Once open, the panel waits without a second
deadline. Fast, complete mapped sequences execute without a panel.

The panel takes no focus and does not resize editing windows. Columns adapt
to the screen, descriptions truncate by display width, and the default panel
occupies at most 12 lines. Larger menus use pages: <C-d> advances and <C-u>
goes back. A paging key is reserved only when multiple pages exist and it is
not a mapped continuation of the current prefix. If both keys conflict,
configure alternatives; commands on hidden pages remain available by typing
them.

==============================================================================
CONFIGURATION AND API                        *better-start-nvim-which-key-api*

init.lua initializes lua/which_key.lua after projects and workspaces:
>lua
    require('which_key').setup {
        modes = { 'n', 'x' },
        groups = {
            ['<leader>p'] = 'Projects',
            ['<leader><Tab>'] = 'Workspaces',
            ['<leader>w'] = 'Windows',
            ['<leader>b'] = 'Buffers',
        },
        max_height = 12,       -- Includes the heading; at least 2.
        min_column_width = 30, -- At least 8 display cells.
        page_down = '<C-d>',   -- One key, including a modified key.
        page_up = '<C-u>',
    }
<
setup({options})                         *better-start-nvim-which-key-setup()*
    Replace the previous setup, index current-buffer mappings, and install
    triggers. Only n (Normal) and x (all Visual selections) are supported.
    Group labels are optional and create no mappings. Invalid modes or panel
    dimensions raise an error.

refresh()                              *better-start-nvim-which-key-refresh()*
    Rediscover current-buffer mappings and replace owned triggers. During an
    active panel or replay, defer work until it can safely run. Call after
    adding or deleting mappings outside the automatic refresh events,
    especially when introducing a new root prefix.

show({prefix})                            *better-start-nvim-which-key-show()*
    Open a prefix immediately, using Vim key notation, and wait for input:
>lua
    require('which_key').show('<leader>p')
<
    Return without action when disabled, another panel is active, or the
    current mode is unsupported. Execution still uses native mappings.

disable()                              *better-start-nvim-which-key-disable()*
    Cancel the panel and remove owned triggers, autocommands, and scratch
    resources. Preserve mappings that have replaced an owned trigger.

Refreshes are coalesced after startup, buffer entry, filetype setup, LSP
attach/detach, script sourcing, and package changes. Opening a prefix also
refreshes its index. An open panel keeps its opening snapshot; execution uses
Neovim's current mappings.

==============================================================================
INPUT SEMANTICS                            *better-start-nvim-which-key-input*

The module installs buffer-local root triggers only where no exact mapping
already exists. An exact <leader> mapping prevents automatic hints under that
root. Exact mappings deeper in a menu return to native resolution, retaining
their timeout and nowait behavior.

Count digits, register selection, cancellation keys, and Normal-mode d, c, y,
r, q, and @ entry points are excluded from automatic triggers. Insert,
command-line, terminal-input, Select, and operator-pending modes receive no
triggers. Temporary Normal commands entered with <C-o> pass through without
hints. Internal <Plug> and script-local mappings are hidden; user mappings
targeting <Plug> remain visible.

Completed input is replayed through native mapping resolution, preserving
counts, registers, selections, recursive mappings, expression mappings, and
<Plug> expansion. The initiating trigger is temporarily detached to prevent
recursion and restored on SafeState, after Neovim finishes resolving input.
Macro playback opens no panel. Window, tab, buffer, or mode changes cancel the
panel so its prefix cannot execute in a new context.

Mapping indexes are cached per buffer and mode, the scratch buffer is reused,
and wiped buffers release their caches. The module uses no polling timers,
global keymap wrappers, or ordinary-keystroke listeners.

==============================================================================
VERIFICATION                        *better-start-nvim-which-key-verification*

Run from the repository root:
>sh
    nvim --headless -u NONE -i NONE -l tests/which_key.lua
    nvim --headless -u NONE -i NONE -l tests/which_key_ui.lua
    nvim --headless -u NONE -i NONE -l tests/which_key_bench.lua
<
The UI suite starts a separate Neovim process with an attached 90 by 28 UI
and sends actual input. It covers prefix timing, counts/registers, Visual
selections, cancellation, macros, repeat, native fallbacks, recursive and
expression mappings, Unicode, paging, resizing, context changes, cleanup,
exact/nowait precedence, and ui2. Differential cases compare final text,
cursor, register, and mode with hints enabled and disabled. Ordinary typing
and fast mapped input must perform no helper mapping scans or window opens.

The benchmark uses an attached 120 by 40 UI and reports 15-sample medians for
100, 1,000, and 5,000 synthetic mappings. Setup includes indexing; refresh
includes discovery and trigger replacement; render/close excludes refresh.
Results are local measurements, not CI timing thresholds.

Run the existing project/workspace, picker, completion, and full startup
checks when changing integration. See AGENTS.md for their commands and state
isolation instructions.
