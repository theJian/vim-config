RUST NATIVE MODULES				       *better-start-nvim-ffi*

`ffi.git` retrieves Git branches and repository status asynchronously so Neovim
can continue working during repository discovery. Call status(dir, callback)
to run a lookup in a worker and receive its result on Neovim's main loop.
Build the required Rust library before importing the module; see
|better-start-nvim-ffi-build|.

Part of |better-start-nvim|.

==============================================================================
BUILD AND TRY					 *better-start-nvim-ffi-build*

The Lua API requires a Neovim build with LuaJIT FFI. With Cargo and a C build
toolchain installed, build and test from the repository root:

>sh
    cargo build --release
    nvim --headless -u NONE -i NONE -l tests/ffi_git.lua
<

The Cargo package is `better-start-nvim` and its library is `ffi`: the build
produces `target/release/libffi.dylib` on macOS, `libffi.so` on Linux, or
`ffi.dll` on Windows. `NVIM_NATIVE_LIBRARY` overrides the absolute library
path. Importing `ffi.git` loads the library immediately and raises an error if
it is unavailable. The loader caches success or failure; restart Neovim after
building or replacing the library.

The release profile disables symbol stripping to avoid the macOS 27 load
failure tracked in rust-lang/rust#157750:
https://github.com/rust-lang/rust/issues/157750

BRANCH API					*better-start-nvim-ffi-branch*

branch({dir}, {callback})		  *better-start-nvim-ffi.git.branch()*

With this repository on Neovim's runtime path:

>lua
    local git = require 'ffi.git'
    local function report(branch, lookup_error)
      if lookup_error then
	vim.notify(lookup_error, vim.log.levels.WARN)
	return
      end
      vim.notify('Branch: ' .. branch)
    end
    local queued, err = git.branch(vim.fn.getcwd(), report)
    if not queued then
      vim.notify(err, vim.log.levels.WARN)
    end
<

`branch(dir, callback)` returns true if queued, or false and a diagnostic when
worker creation or queueing fails. Relative paths resolve against Neovim's
current directory when `branch` is called. Rejected requests do not invoke the
callback. Invalid Lua argument types and paths containing NUL bytes raise an
error. Queued requests invoke the callback on Neovim's main loop with a branch
string, or an empty string and diagnostic on failure. Repository discovery
searches parent directories and supports linked worktrees. Detached HEAD uses
libgit2's unique object-ID abbreviation, starting at `core.abbrev` (default
seven digits) and extending when needed to avoid ambiguity. Unborn HEAD and
non-repositories yield lookup failures.

Requests cannot be individually cancelled; slow filesystems can occupy a libuv
worker.

Filesystem paths preserve raw bytes on Unix; other targets accept UTF-8 paths.

STATUS API					*better-start-nvim-ffi-status*

status({dir}, {callback})		  *better-start-nvim-ffi.git.status()*

>lua
    local function report(status, lookup_error)
      if not status then
	vim.notify(lookup_error, vim.log.levels.WARN)
	return
      end
      vim.notify(status.branch .. ' +' .. status.tracked)
    end
    local queued, err = require('ffi.git').status(vim.fn.getcwd(), report)
    if not queued then
      vim.notify(err, vim.log.levels.WARN)
    end
<

Uses branch()'s discovery, argument validation, queueing, and main-loop callback
rules. On success, the callback receives a table with these fields:

    branch      Branch name or detached commit ID; includes unborn branches.
    tracked     Changed tracked files, staged or unstaged, excluding conflicts.
    untracked   Untracked files, excluding ignored files.
    ahead       Commits ahead of the locally known upstream.
    behind      Commits behind the locally known upstream.
    conflicts   Conflicted files, counted separately from tracked changes.

File counts cover the entire repository, including individual untracked files
inside new directories. Each changed file is counted once, including files
with both staged and unstaged changes. A staged deletion with a recreated file
at the same path counts as one tracked change. Counts reflect saved changes.
Ahead/behind are zero without a usable upstream, including detached and unborn
HEADs. This call never fetches remotes or spawns Git commands.

Lookup failures invoke the callback with nil and a diagnostic.

BOUNDARY AND INTEGRATION		      *better-start-nvim-ffi-boundary*

`src/git.rs` uses git2 for repository discovery. `src/lib.rs` translates its
results into the C ABI. `lua/ffi/loader.lua` resolves the library and checks
the Git branch and status symbols; `lua/ffi/git.lua` manages request buffers and
libuv worker scheduling for the asynchronous Lua API. The loader retains the
library handle for the module's lifetime. Workers load their own handles.
Rebuild the library after changing native code or its Lua calling contract.

C ABI						   *better-start-nvim-ffi-abi*

ffi_git_branch()			  *better-start-nvim-ffi_git_branch()*
>c
    int32_t ffi_git_branch(const char *path, char *out, size_t capacity);
<
The caller owns both buffers. path must point to a readable NUL-terminated
filesystem path; Unix accepts raw path bytes and other targets require UTF-8.
out must point to capacity writable bytes. Keep both buffers valid and
non-overlapping throughout the call. capacity includes space for the output
terminator.

Returns the written byte length excluding the NUL terminator, -1 for lookup or
argument failure, -2 for insufficient capacity, or -3 for a caught Rust panic.
Successful output is NUL-terminated; discard output on failure. Panics are
caught when Rust uses unwinding; process aborts cannot be caught.

Lua retries small buffers up to 64 KiB. Diagnostic strings currently
distinguish load/queue failures and native status codes, not individual
libgit2 errors.

ffi_git_status()			  *better-start-nvim-ffi_git_status()*
>c
    typedef struct {
        size_t tracked;
        size_t untracked;
        size_t ahead;
        size_t behind;
        size_t conflicts;
    } FfiGitCounts;
    int32_t ffi_git_status(const char *path, char *out, size_t capacity,
                          FfiGitCounts *counts);
<
Uses ffi_git_branch()'s path, branch buffer, and return-code rules. counts must
point to writable, aligned storage for one FfiGitCounts. All three regions must
remain valid and non-overlapping throughout the call. A successful call writes
both the NUL-terminated branch text and all counts. Null pointers are rejected;
failed calls leave outputs unchanged. Discard both outputs on failure.

==============================================================================
STATUSLINE INTEGRATION			    *better-start-nvim-ffi-statusline*

`lua/better_statusline.lua` uses `ffi.git.status` for branch and count requests.
It caches Git results and bar strings, so redraws use cached data while lookups
run in workers. A missing library fails at import, and rejected worker requests
raise errors. See |better-start-nvim-statusline| for displayed information and
refresh behavior.

VERIFICATION				  *better-start-nvim-ffi-verification*

>sh
    cargo fmt --check
    cargo clippy --offline --locked -- -D warnings
    cargo build --release --offline --locked
    nvim --headless -u NONE -i NONE -l tests/ffi_git.lua
    nvim --headless -u NONE -i NONE -l tests/better_statusline.lua
<

The native test creates disposable repositories and exercises worker
callbacks, nested discovery, linked worktrees, unborn and detached HEAD,
Unicode names, staged and unstaged changes, nested untracked and ignored files,
renames, deletions, upstream divergence, conflicts, concurrent requests,
caller-owned buffer limits, invalid arguments, and a missing library. Git is
required for these test fixtures.
Offline Cargo commands require dependencies to be cached already.
